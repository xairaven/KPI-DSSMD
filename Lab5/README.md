# Лаб. 5 — Абітурієнт (сторонні бібліотеки)

Android-додаток на Tauri (Rust + React/TypeScript), побудований на основі
Лаб. 4. Домен: абітурієнт (ID, Прізвище, Ім'я, По-батькові, Адреса,
Телефон, Оцінки).

Завдання додає до застосунку сторонні бібліотеки різними методами та
вимагає висновок про зручність цих методів. У цій роботі використано два
методи:

- **npm/pnpm-реєстр** (звичайний спосіб) — бібліотека `fuse.js` на
  фронтенді, для нечіткого (typo-tolerant) пошуку абітурієнтів за
  прізвищем на екрані "Пошук".
- **git-залежність** (не crates.io) — крейт `qrcode`, підключений
  безпосередньо з GitHub-репозиторію (`kennytm/qrcode-rust`, тег
  `v0.14.1`), для генерації QR-коду з даними абітурієнта на екрані
  "Абітурієнти".

## Структура

- `src-tauri/src/applicant.rs` — Model: сутність `Applicant` і чисті
  функції бізнес-логіки (середній бал, незадовільні оцінки, поріг,
  напівпрохідний бал). Нічого не знає про Tauri чи UI.
- `src-tauri/src/repository.rs` — Model: спільне мутабельне сховище
  (`Mutex`, керований стан Tauri), ініціалізоване даними з файлу.
- `src-tauri/src/sample.rs` — початковий масив із 10 абітурієнтів,
  використовується як запасний варіант, якщо файл даних відсутній
  або пошкоджений.
- `src-tauri/src/storage.rs` — Model: читання/запис абітурієнтів у
  JSON-файл (`applicants.json`) у каталозі даних застосунку.
- `src-tauri/src/screen/` — Controller: по одному модулю на кожен пункт
  завдання плюс екран введення/редагування та генерація QR-коду:
  - `failing.rs` → (a) незадовільні оцінки
  - `threshold.rs` → (б) поріг середнього балу
  - `top.rs` → (в) топ-N та напівпрохідний бал
  - `students.rs` → список, додавання, редагування, видалення
  - `qr.rs` → (новий у цій роботі) генерація SVG QR-коду з даними
    одного абітурієнта за допомогою крейту `qrcode`, підключеного
    через git-залежність
- `src-tauri/src/lib.rs` — читає `applicants.json` під час `setup()`
  (перед тим, як стан стає керованим), підписується на
  `RunEvent`/`WindowEvent`, щоб журналювати зміни стану життєвого циклу
  Activity, і зберігає дані у файл при `Suspended`/`Exit`/`CloseRequested`.
- `src/screens/` — View: `Home.tsx` (меню), та по одному екрану на
  кожен Controller вище. Жодної бізнес-логіки, лише відображення та
  виклик `invoke()`.
  - `Search.tsx` — пошук абітурієнтів за прізвищем; у цій роботі
    замінений на нечіткий пошук через `fuse.js` (весь список
    завантажується один раз, а фільтрація відбувається на клієнті при
    кожній зміні поля вводу).
  - `Students.tsx` — список/форма, а також кнопка "QR-код" у кожному
    рядку, що показує SVG QR-код з даними абітурієнта.
- `src/components/ApplicantTable.tsx` — спільна таблиця, яку
  перевикористовують екрани звітів (a/б/в).

## Запуск

```sh
pnpm install
pnpm tauri android dev   # Android-емулятор
pnpm tauri dev            # десктоп, для швидкої перевірки
```

### Перевірка

На екрані "Пошук" введіть прізвище з однією-двома помилками — список
усе одно відфільтрується завдяки нечіткому пошуку `fuse.js`. На екрані
"Абітурієнти" натисніть кнопку "QR-код" біля будь-якого рядка — під
таблицею з'явиться згенерований QR-код; його можна зчитати камерою
телефона (поза емулятором), щоб переконатися, що він справді кодує дані
абітурієнта.
