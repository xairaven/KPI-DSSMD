# Лаб. 6 — Абітурієнт (збереження в БД)

Android-додаток на Tauri (Rust + React/TypeScript), побудований на основі
Лаб. 5. Домен: абітурієнт (ID, Прізвище, Ім'я, По-батькові, Адреса,
Телефон, Оцінки).

Завдання — додати збереження всіх даних програми в БД Android та вибірку
їх за потреби. У цій роботі файлове сховище на JSON (Лаб. 2–5) замінено
на SQLite через крейт `rusqlite` (crates.io, з фічею `bundled`, яка
компілює SQLite з джерельного коду — тож збірка працює і під Android).
Решта архітектури (спільний `Repository` у пам'яті, команди `screen::*`,
збереження за подіями життєвого циклу Activity) не змінювалась — заміна
торкнулась лише самого сховища.

## Структура

- `src-tauri/src/applicant.rs` — Model: сутність `Applicant` і чисті
  функції бізнес-логіки (середній бал, незадовільні оцінки, поріг,
  напівпрохідний бал). Нічого не знає про Tauri чи UI.
- `src-tauri/src/repository.rs` — Model: спільне мутабельне сховище
  (`Mutex`, керований стан Tauri) у пам'яті, ініціалізоване даними з БД.
- `src-tauri/src/sample.rs` — початковий масив із 10 абітурієнтів,
  яким заповнюється щойно створена (порожня) база даних при першому
  запуску.
- `src-tauri/src/storage.rs` — Model: читання/запис абітурієнтів у
  SQLite-базі (`applicants.db`) у каталозі даних застосунку. Таблиця
  `applicants` зберігає оцінки як рядок через кому (`grades TEXT`), бо
  SQLite не має типу "масив". `load()` створює таблицю за потреби й
  заповнює її зразковими даними лише тоді, коли файл бази щойно
  створено; `save()` повністю перезаписує таблицю (`DELETE` + `INSERT`)
  поточним станом `Repository` — так само, як раніше перезаписувався
  весь JSON-файл.
- `src-tauri/src/screen/` — Controller: по одному модулю на кожен пункт
  завдання плюс екран введення/редагування та генерація QR-коду:
  - `failing.rs` → (a) незадовільні оцінки
  - `threshold.rs` → (б) поріг середнього балу
  - `top.rs` → (в) топ-N та напівпрохідний бал
  - `students.rs` → список, додавання, редагування, видалення
  - `qr.rs` → генерація SVG QR-коду з даними одного абітурієнта
- `src-tauri/src/lib.rs` — читає `applicants.db` під час `setup()`
  (перед тим, як стан стає керованим), підписується на
  `RunEvent`/`WindowEvent`, щоб журналювати зміни стану життєвого циклу
  Activity, і зберігає повний знімок даних у базу при
  `Suspended`/`Exit`/`CloseRequested`.
- `src/screens/` — View: `Home.tsx` (меню), та по одному екрану на
  кожен Controller вище. Жодної бізнес-логіки, лише відображення та
  виклик `invoke()`.
  - `Search.tsx` — нечіткий (typo-tolerant) пошук абітурієнтів за
    прізвищем через `fuse.js`.
  - `Students.tsx` — список/форма, а також кнопка "QR-код" у кожному
    рядку, що показує SVG QR-код з даними абітурієнта.
- `src/components/ApplicantTable.tsx` — спільна таблиця, яку
  перевикористовують екрани звітів (a/б/в).

## Запуск

```sh
pnpm install
pnpm tauri android dev   # Android-емулятор
pnpm tauri dev            # десктоп, для швидкої перевірки
```

### Перевірка

Додайте, відредагуйте та видаліть кількох абітурієнтів на екрані
"Абітурієнти", після чого згорніть застосунок або закрийте його (це
викликає `Suspended`/`CloseRequested`/`Exit` і журналює відповідний
запис про збереження), а потім запустіть його знову — список має
відображати саме той стан, у якому його залишили: нові абітурієнти,
внесені правки та видалені записи. Дані зберігаються у файлі
`applicants.db` у каталозі даних застосунку.
